Break test: bugs found and fixed

Today I tried to break the Phase A structure step on purpose. I used two test workbooks that hold every structural problem we handle, 31 deliberately broken files, and real files saved by Excel. I also ran the local AI model (llama3.2:3b) against the same workbooks. Every bug I found is fixed and has an automated test.

Bugs and fixes

#What went wrongWhat we changedStatus
1A merged heading over an empty column made one table split in two. A hidden column next to it became its own one-column table.The table finder now treats merged cells as joined and won't split a table through them.Fixed
2An empty spacer column inside a table disappeared without being reported.It is now listed as a dropped column, so the analyst can see it.Fixed
3When a merged title was removed from above a table, it was left out of the merged-cell count.Title merges are now counted with the rest.Fixed
4Password-protected .xls and .ods files were reported as "unreadable", which doesn't tell the analyst what to do.They are now reported as password-protected, with the message "Remove the password".Fixed
5A block of cells holding only spaces was treated as a real table.Cells that hold only spaces are now ignored.Fixed
6False warnings: every run without the AI model said "AI review fell back", and a CSV's file name was flagged as a bad sheet name.Both warnings are removed.Fixed
7Excel had to "repair" the review workbook on open, because cell formats and comments from one sheet were applied to another.Each sheet now gets only its own formats and comments. Excel opens the file cleanly.Fixed
8Opening and saving the review workbook in Excel, with no changes, created fake edits (Excel rounds numbers to 15 digits).Numbers are now compared the way Excel stores them. An untouched file imports with no changes, and real edits still apply.Fixed
9When only the model name was configured, the AI decision log didn't record which exact model version answered.The model version reported by the AI server is now saved with every decision.Fixed

AI model test (llama3.2:3b)

  • It ran on all three test files with no crashes. Every answer was valid.
  • The cleaned tables were identical with and without the AI.
  • Every time the model disagreed with the rules, the model was wrong. The safety checks blocked every wrong answer, so no bad change reached the data.
  • The cost was time (about 5–6 minutes per workbook) and 2 unnecessary warnings per workbook.

Open items and decisions needed

  • Decision Ask the AI only about close calls (review: near_ties). This cut AI calls by two-thirds (150 to 51) and removes the unnecessary warnings.
  • Decision Reduce the AI's context size in the spec. On a 4 GB GPU this makes each call about 21% faster.
  • Open A side calculation placed right next to a table, with no empty column between, is read as part of the table. The analyst can exclude it in the review workbook.
  • Open Very large sheets are held fully in memory. Very large sheets are refused with a "sheet too large" message rather than run out of memory.
  • Open Converting .xls, .xlsb and .ods files is untested because LibreOffice isn't installed on this machine.
